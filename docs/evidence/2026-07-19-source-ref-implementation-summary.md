# 证据回溯能力实施总结（阶段 A / A+）

- 实施日期：2026-07-19
- 关联提交：`7d75a9a`（阶段 A）、`904cb07`（并行路径补齐）、`98ce0b3`（阶段 A+）
- 目标：让行程中的“已确认事实”能回到本次会话里真实执行过的检索结果，而不是只保留模型填写的链接文字。

## 1. 一句话结论

现在，一个已确认的事实必须引用 `web_search` 返回的 `source_id`。系统会核对该编号是否属于当前会话、是否对应同一个 URL；伪造、跨会话复用或缺少编号的引用都会被拒绝。

这解决的是“来源引用可回溯”，不代表系统能证明模型对网页内容的概括完全正确。

## 2. 实施前后对比

| 项目 | 实施前 | 阶段 A | 阶段 A+（当前） |
|---|---|---|---|
| 行程活动的依据 | 没有统一字段记录推荐理由和来源 | 可保存角色、推荐理由、待复核标记和来源记录 | 保持阶段 A 的结构，并增加来源编号 |
| 已确认事实 | 模型可自行填写链接；系统无法确认该链接是否来自本次搜索 | 要求来源类型、事实类型和可信度符合规则 | 必须带本会话搜索结果返回的 `source_ref` |
| 主要景点 | 无可靠来源要求 | 没有可靠事实来源时，必须标记“待复核” | 同时要求已确认事实能回到真实搜索结果 |
| 用户内容 | 可能被当成已确认事实 | 小红书和用户内容不能标为“已确认事实” | 规则不变 |
| 并行排程 | 无证据字段和校验，无法保存证据 | 初版只覆盖普通排程路径 | Worker 提交时也做同样校验；单天失败可单独重试 |
| 被淘汰的候选 | 通常直接丢失 | 以结构化记录保存淘汰原因和重新考虑条件 | 规则不变，并会进入最终行程说明 |
| 最终交付物 | 不会集中展示待复核项或淘汰项 | 自动生成“出发前需复核”“已排除/暂缓项目”章节 | 规则不变 |

## 3. 当前工作方式

```text
web_search 返回网页结果
  -> 为每个 http(s) 结果登记 source_id
  -> 模型把 source_id 原样写入 evidence.source_ref
  -> 写入日程前核对编号、会话和 URL
  -> 通过：保存到行程
  -> 不通过：拒绝写入，并给出可修复提示
```

来源登记按“会话 + URL”生成稳定编号。同一会话重复搜索同一个 URL，编号不变；其他会话不能使用这个编号。

## 4. 规则与结果

| 情况 | 当前结果 |
|---|---|
| 小红书或用户内容被写成已确认事实 | 拒绝写入（`UGC_FACT_NOT_CONFIRMABLE`） |
| 主要景点没有可靠事实来源，却未标“待复核” | 拒绝写入（`ANCHOR_NEEDS_RELIABLE_SOURCE`） |
| `source_ref` 编号不存在或来自别的会话 | 拒绝写入（`UNKNOWN_SOURCE_REF`） |
| 引用编号对应的 URL 与填写 URL 不一致 | 拒绝写入（`SOURCE_REF_URL_MISMATCH`） |
| 已确认事实未带来源编号 | 拒绝写入（`CONFIRMED_FACT_NEEDS_SOURCE_REF`） |
| 信息不足但仍值得推荐 | 可以保存，但必须标“待复核” |

## 5. 覆盖范围与边界

### 已覆盖

- 普通排程：`save_day_plan` 和 `replace_all_day_plans`。
- 并行排程：Day Worker 提交候选日程时即校验；失败只影响该天的重试，不会拖到全部日程汇总后才发现。
- 最终文档：从行程状态生成待复核项和淘汰项。
- 兼容旧数据：旧行程没有证据字段时仍可读取；未接入来源登记的旧调用只保留原有格式检查。

### 未覆盖

- 不验证网页是否真实、是否最新，或网页内容是否支持模型写出的结论。
- 不保证最终摘要逐字保留来源编号；摘要仍由模型压缩生成。
- 当前只把 `web_search` 的结果登记为可引用来源；其他检索工具需要单独接入才可提供同样的编号。

## 6. 验证情况

实现包含以下自动检查：

- 来源编号的生成、重复登记、跨会话隔离和非法 URL 拒绝。
- 伪造编号、编号与 URL 不一致、已确认事实缺编号的拒绝。
- 普通和并行排程两条路径的写入校验。
- 证据字段、淘汰候选和最终交付物的保存与读取。

提交记录中的全量检查结果：阶段 A 为 2,075 项通过；补齐并行路径后为 2,086 项通过；阶段 A+ 为 2,100 项通过。
