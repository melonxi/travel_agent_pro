role × transient × XML-like tag

Travel Agent Pro 的上下文工程不再只靠 LLM 原生 role 分类，而是用三维共同表达——role 负责 provider 通道，transient 负责生命周期，tag 负责告诉模型这段 user-role 内容到底是用户输入、运行时上下文，还是应用事件。

🧊 三维定义
🛤️

role — 通道

解决 "模型用什么通道解读" 的问题。SYSTEM = 规则层，USER = 内容层，ASSISTANT = 对话层，TOOL = 工具层。

SYSTEM USER ASSISTANT TOOL

⚠️ 只靠 role：无法区分"用户说了什么"和"应用注入了什么"
⏳

transient — 生命周期

解决 "这条消息活多久" 的问题。True = 每轮重建、不落盘；False = 写入 append-only 历史永久保留。

🔄 transient=True — 每轮重建
💾 transient=False — 持久化

⚠️ 只靠 transient：无法传递跨轮事实（如压缩后的历史摘要）
🏷️

XML-like tag — 语义边界

解决 "这段 user-role 内容到底是什么" 的问题。同一个 USER 通道里，tag 二次区分真实输入 vs 运行时状态 vs 应用事件。

<turn_context> <runtime_notice> <app_event> <!-- soul:xxx -->

⚠️ 只靠 tag：没有 provider 通道语义就无法被正确路由

⏳ 生命周期流程
每轮开始
├── 重建 static_system 🔄 transient  ← 每轮从 plan + phase_prompt + soul 重新生成
├── 加载 persisted_history 💾 persistent  ← 从 SQLite messages 表恢复
├── flush pending_notes → <runtime_notice> 🔄 transient  ← 验证反馈等
├── 注入 <turn_context> 🔄 transient  ← 当前状态+时间+工具+记忆
│
├── [LLM 迭代循环]
│     ├── tool 调用 → TOOL 💾 persistent
│     ├── 验证反馈 → <runtime_notice kind="validation"> 🔄 transient
│     ├── 修复提示 → <runtime_notice kind="repair"> 🔄 transient
│     └── 反思注入 → <runtime_notice kind="reflection"> 🔄 transient
│
├── [阶段转换]
│     ├── flush 当前 epoch 持久化消息
│     ├── context_epoch += 1
│     ├── 重建 runtime messages（static_system + handoff + turn_context）
│     └── backtrack → <app_event kind="backtrack"> 💾 persistent
│

      ├── compressible: 其余消息
      └── 压缩结果 → <app_event kind="history_summary"> 💾 persistent
🎯 关键设计决策
决策 选择 理由
turn_context 用 USER 角色 USER 与真实用户消息在同一个 provider 通道，但 tag 内声明式指令阻止模型当作用户请求
runtime_notice 用 USER 角色 USER 运行时提示不能覆盖 system 规则，只是补充信息；tag 声明"不是用户请求"
app_event 用 USER 角色 USER 应用生成的历史事件是事实而非规则；tag 声明"不是系统规则"
static_system 用 transient=True True 系统 prompt 每轮重建（soul/状态/阶段都可能变化），不需在历史中累积
turn_context 用 transient=True True 规划状态每轮刷新，旧状态无保留价值；下次轮从 TravelPlanState 重新生成
runtime_notice 用 transient=True True 验证/修复/反思提示只服务于当前 LLM 轮次，下一轮由新的验证结果替代
app_event 用 transient=False False 历史摘要、回退通知是跨轮事实，需要持久化到 append-only 历史
阶段交接用 ASSISTANT 角色 ASSISTANT 交接说明是"助手承上启下"而非系统规则，放在对话流中更自然
tag 内声明式指令 内嵌描述 让模型在每个 block 内即可理解语义边界，无需外部查找规则
权威排序显式声明 _tagged_context_rules() 防止模型被记忆 block 覆盖当前状态
